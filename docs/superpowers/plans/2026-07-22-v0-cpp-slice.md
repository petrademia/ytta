# YTTA v0 Implementation Plan (Fixture + C++ Slice)

> **For agentic workers:** Implement task-by-task. Checkboxes track progress. Do **not** port Go/Rust/Java in this plan.

**Goal:** Freeze shared v0 message/fixture/golden shapes, then ship an in-process C++ thin tick→decide→execute slice that produces the golden output.

**Architecture:** Single C++ binary wires `TickSource → Strategy → OrderGateway → MatchingEngine` in-process (function calls or simple queues). Fixture NDJSON in; canonical event NDJSON out. C++ output becomes the golden other languages must match later.

**Tech Stack:** C++20, CMake, existing `cpp/` tree. Shared artifacts under `shared/` + `specs/`. No new network deps. Prefer stdlib; JSON parse may use a tiny single-header or line-oriented NDJSON with a minimal hand parser if that stays smaller.

**Upstream locked decisions (do not reopen):**
`docs/superpowers/specs/2026-07-22-v0-learning-path-design.md`

## Global Constraints

- One instrument (`INSTR1`), one strategy, one book
- Actions only: `NOOP | NEW_ORDER | CANCEL`
- Integer `price` and `qty` (not floating point)
- Fixture replay only; paper execute; in-process only
- Absolute µs latency budgets are **not** pass/fail; reporting p50/p99 is required
- Keep existing thread/mem-pool demos working; add a new `ytta_v0` target
- Existing `shared/schemas/tick.schema.json` uses floats + RFC3339 timestamps — **replace/extend for v0 integers**; do not leave conflicting schemas
- Do not implement Go/Rust/Java ports, sockets, REPLACE, live feeds, or risk engine

## Canonical message shapes (freeze these; tweak only with rationale in `specs/v0_messages.md`)

All streams are **NDJSON**, one JSON object per line, UTF-8, no pretty-print in goldens.

### Tick (input fixture)

```json
{"type":"tick","ts_ns":1000,"instrument":"INSTR1","side":"BUY","price":100,"qty":5,"seq":1}
```

- `side`: `BUY` | `SELL` (aggressor / trade side for strategy; book uses bid/ask via order side)
- `price`, `qty`: positive integers
- `ts_ns`: integer nanoseconds (fixture-defined; not wall clock)
- `seq`: strictly increasing in the fixture

### Strategy action (internal / logged)

```json
{"type":"action","ts_ns":1001,"action":"NEW_ORDER","cl_ord_id":1,"side":"BUY","price":100,"qty":5,"reason":"cross"}
{"type":"action","ts_ns":1002,"action":"CANCEL","cl_ord_id":1,"reason":"done"}
{"type":"action","ts_ns":1003,"action":"NOOP","reason":"flat"}
```

### Order to engine

```json
{"type":"order","ts_ns":1001,"cl_ord_id":1,"op":"NEW","side":"BUY","price":100,"qty":5}
{"type":"order","ts_ns":1002,"cl_ord_id":1,"op":"CANCEL"}
```

### Ack / reject

```json
{"type":"ack","ts_ns":1001,"cl_ord_id":1,"status":"ACCEPTED"}
{"type":"ack","ts_ns":1002,"cl_ord_id":99,"status":"REJECTED","reason":"unknown_id"}
```

### Fill

```json
{"type":"fill","ts_ns":1001,"cl_ord_id":1,"price":100,"qty":5,"liquidity":"TAKER"}
```

### Market data (engine → strategy)

```json
{"type":"md","ts_ns":1001,"instrument":"INSTR1","best_bid":99,"best_ask":101,"best_bid_qty":10,"best_ask_qty":8}
```

Use `null` or omit empty side fields only if documented; prefer always present integers with `0` qty meaning empty side.

### Latency summary (stderr or trailer; **not** part of golden compare)

```json
{"type":"latency","count":N,"p50_ns":...,"p99_ns":...}
```

### Golden stream rules

1. Golden file contains only: `action`, `ack`, `fill`, `md` (optional: include `order` if useful; pick one and document — **recommend include `ack`+`fill`+`action`, exclude raw `order` duplicates**).
2. Sort key: (`ts_ns`, stable type order: `md`, `action`, `ack`, `fill`), then `cl_ord_id`.
3. Same fixture must yield identical golden bytes (or normalized canonical form) across future language ports.
4. Strategy for v0 must be **deterministic** and documented in `specs/v0_messages.md` (example below).

### Suggested deterministic strategy (v0)

On each tick:
- If tick `side==BUY` and `price >= best_ask` and `best_ask_qty>0`: `NEW_ORDER` SELL? No — keep it simple:
- **Simpler:** maintain a resting BUY at `tick.price - 1` qty 1 when flat; on adverse tick cancel; when tick crosses an implied fair value place a TAKER order that matches resting liquidity seeded by the fixture/engine bootstrap.

**Even simpler (preferred for first golden):**

1. Engine starts with seed book from fixture header or first N ticks marked as `book_seed` — OR strategy places one resting BUY, later tick causes a SELL that matches.
2. Minimum path the golden must exercise: at least one `NEW_ORDER`, one `CANCEL`, one `FILL`, several `NOOP`s.

Document the exact strategy rules in `specs/v0_messages.md` so ports do not reverse-engineer C++.
