# YTTA v0 Go Port Plan

> **For agentic workers:** Port only. Do not change the frozen golden or C++ reference unless you find a spec bug (then stop and report).

**Goal:** Idiomatic Go implementation of the v0 in-process tick-to-trade slice that byte-matches `shared/fixtures/v0/golden.ndjson`.

**Architecture:** Same components as C++: TickSource → Strategy → OrderGateway → MatchingEngine + LatencyProbe. In-process only. Behavior from `specs/v0_messages.md`, not from reverse-engineering C++ internals.

**Tech Stack:** Go 1.22 (`go/go.mod`), stdlib only (`encoding/json`, `flag`, `bufio`, `sort`, `time`). Keep existing `cmd/ytta` thread demo working; add a separate v0 entrypoint.

## Global Constraints

- Follow `specs/v0_messages.md` exactly (strategy rules, golden sort, field omit rules)
- Input: `shared/fixtures/v0/ticks.ndjson`
- Golden: `shared/fixtures/v0/golden.ndjson` — **do not edit** to make Go pass
- Integer price/qty; `INSTR1`; `NOOP|NEW_ORDER|CANCEL` only
- Latency JSON on stderr; not part of golden compare; not a CI µs gate
- Do not touch `cpp/`, `rust/`, `java/` except Makefile test wiring if needed
- Do not reopen architecture; no sockets; no REPLACE; no live feeds

## JSON formatting (golden-critical)

- Emit compact JSON with **stable key order** matching C++ golden lines (see `shared/fixtures/v0/golden.ndjson`)
- Prefer hand-built `fmt.Sprintf` / `strings.Builder` for golden lines (stdlib `json.Marshal` map key order is unsafe for byte compare)
- Omit fields exactly as C++ does (`NOOP` has no `cl_ord_id`; accepted ack has no `reason`)
- Sort before write: `(ts_ns ASC, type_rank ASC, cl_ord_id ASC)` with ranks `md=0, action=1, ack=2, fill=3`
