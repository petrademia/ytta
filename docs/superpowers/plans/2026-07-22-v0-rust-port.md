# YTTA v0 Rust Port Plan

> **For agentic workers:** Port only. Do not change the frozen golden, specs, or C++/Go references unless you find a spec bug (then stop and report).

**Goal:** Idiomatic Rust implementation of the v0 in-process tick-to-trade slice that byte-matches `shared/fixtures/v0/golden.ndjson`.

**Architecture:** Same components: TickSource → Strategy → OrderGateway → MatchingEngine + LatencyProbe. Behavior from `specs/v0_messages.md`.

**Tech Stack:** Rust 2021 edition (`rust/Cargo.toml`). Prefer **stdlib only**. If you add a crate, justify it; do not pull in a full async stack. Stable golden formatting must not depend on `serde_json` map key order — hand-format golden lines (or equivalent deterministic writer).

## Global Constraints

- Follow `specs/v0_messages.md` exactly
- Input: `shared/fixtures/v0/ticks.ndjson`
- Golden: `shared/fixtures/v0/golden.ndjson` — **do not edit**
- Integer price/qty; `INSTR1`; `NOOP|NEW_ORDER|CANCEL`; in-process only
- Latency JSON on stderr; not a µs CI gate
- Keep existing thread demo binary working (`cargo run` / current `main`)
- Do not touch `cpp/`, `go/`, `java/` except root Makefile rust-test / rust-run-v0 wiring
- Do not port Java in this plan

## JSON formatting (golden-critical)

- Compact NDJSON, key order identical to C++/Go golden lines
- Sort: `(ts_ns ASC, type_rank ASC, cl_ord_id ASC)` with `md=0, action=1, ack=2, fill=3`
- Omit fields like the golden (`NOOP` no `cl_ord_id`; accepted ack no `reason`)
