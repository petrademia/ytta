# YTTA v0 Java Port Plan

> **For agentic workers:** Port only. Do not change the frozen golden, specs, or C++/Go/Rust references unless you find a spec bug (then stop and report).

**Goal:** Idiomatic Java 17 implementation of the v0 in-process tick-to-trade slice that byte-matches `shared/fixtures/v0/golden.ndjson`.

**Architecture:** Same components: TickSource → Strategy → OrderGateway → MatchingEngine + LatencyProbe. Behavior from `specs/v0_messages.md`.

**Tech Stack:** Java 17, Maven (`java/pom.xml`). Keep JUnit Jupiter for tests. Prefer **no new runtime deps** (no Gson/Jackson required) — hand-format golden NDJSON lines for stable key order. Existing `com.ytta.App` thread demo must keep working.

## Global Constraints

- Follow `specs/v0_messages.md` exactly
- Input: `shared/fixtures/v0/ticks.ndjson`
- Golden: `shared/fixtures/v0/golden.ndjson` — **do not edit**
- Integer price/qty; `INSTR1`; `NOOP|NEW_ORDER|CANCEL`; in-process only
- Latency JSON on stderr; not a µs CI gate
- Do not touch `cpp/`, `go/`, `rust/` except root Makefile java-test / java-run-v0 wiring
- This completes language parity for v0 — do not start Stage 1 (hot-path primitives) here

## JSON formatting (golden-critical)

- Compact NDJSON, key order identical to C++/Go/Rust golden lines
- Sort: `(ts_ns ASC, type_rank ASC, cl_ord_id ASC)` with `md=0, action=1, ack=2, fill=3`
- Omit fields like the golden (`NOOP` no `cl_ord_id`; accepted ack no `reason`)
- Do **not** use unordered `Map` JSON serializers for golden output

## Fixture path in tests

Resolve golden/fixture relative to repo root (e.g. walk up from `user.dir` / surefire cwd, or use a path that works when `make java-test` runs from repo root). Document the assumption.
